# Prompt Battle

프롬프트를 입력해 주어진 UI 목표를 달성하는 **실시간 경쟁 게임**입니다. 플레이어는 목표 화면을 보고 그것을 재현하는 프롬프트를 작성하고, AI(Claude)가 그 프롬프트로 UI를 구현한 뒤 채점 기준과 비교해 점수를 매깁니다. 호스트 화면에 등수가 표시됩니다.

- **가볍게**: 프로덕션 의존성은 `ws` 하나. 나머지는 전부 Node 내장 모듈. 프론트엔드는 빌드 단계 없는 순수 ES 모듈 + 기본 CSS.
- **서버 권위**: 게임 phase·타이머·제출·채점·문제 선택은 모두 서버가 결정합니다. 클라이언트는 서버가 내려주는 상태를 그리기만 합니다.

---

## 요구사항

- **Node.js >= 24** (내장 `node:sqlite` 안정 버전 사용 — 별도 DB 라이브러리·컴파일 불필요)

## 설치

```bash
npm install
```

`.env.example`를 복사해 `.env`를 만듭니다:

```dotenv
PORT=3000
ADMIN_PASSWORD=change-me
ANTHROPIC_API_KEY=sk-ant-...     # 없으면 FakeProvider로 폴백 (아래 참고)
CLAUDE_MODEL=claude-opus-4-8
```

> **API 키가 없어도 됩니다.** `ANTHROPIC_API_KEY`가 없으면 서버가 `FakeProvider`로 폴백해 전체 흐름(구현·채점·결과)을 시험할 수 있습니다. 실제 UI 구현/채점 품질을 보려면 키를 넣으세요.

## 문제 시드

50개의 컴포넌트 단위 UI 문제 세트가 포함되어 있습니다 (`seed/`). DB에 넣으려면:

```bash
npm run seed              # 아직 없는 문제만 추가 (제목 기준 멱등)
npm run seed -- --reset   # 기존 문제를 모두 지우고 50개 재삽입
```

DB 파일은 `data/app.sqlite`에 생성됩니다 (git 무시). 경로를 바꾸려면 `DB_PATH` 환경변수를 사용하세요.

## 실행

## 로컬 / LAN 호스팅

서버는 모든 네트워크 인터페이스에 바인딩되므로, **같은 네트워크(LAN)** 의 다른 기기(노트북·휴대폰)는 위에 출력된 **LAN URL**로 바로 접속할 수 있습니다. 별도 배포 없이 호스트 PC 한 대로 현장 이벤트를 진행할 수 있습니다.

- 접속이 안 되면 OS 방화벽에서 해당 포트를 허용하세요.
- 인터넷 배포도 동일 서버를 그대로 올리면 됩니다 (Node 프로세스 하나).

## 게임 진행 방법

### 사전 준비 (관리자 콘솔 `/admin/index.html`)

1. `ADMIN_PASSWORD`로 로그인.
2. **계정**: 플레이어가 사용할 이름들을 추가합니다 (비밀번호 없음 — 방 코드로 게이트).
3. **문제**: 문제를 만들거나 수정합니다. 시드된 50개가 이미 있으면 그대로 써도 됩니다.

### 호스트 (`/host/`)

1. 관리자 비밀번호로 진입 → **방 코드**가 생성됩니다. 이 코드를 플레이어에게 알려주세요.
2. 플레이어들이 입장하면 로비 목록에 나타납니다.
3. **문제 선택** — 4가지 방식:
   - **Direct pick**: 목록에서 문제 직접 선택
   - **Roulette**: 전체 문제 대상 슬롯머신 회전 (서버가 당첨 결정)
   - **Category roulette**: 카테고리로 필터 후 룰렛
   - **Pick + random variation**: 문제를 고르면 서버가 그 문제의 base 또는 등록된 바리에이션 중 하나를 랜덤 선택 (숨김)
   - 선택 시 문제 난이도에 따른 제한시간이 자동 설정됩니다.
4. **Start** → 게임 시작. 대시보드에서 각 플레이어의 프롬프트가 **실시간**으로 표시됩니다 (플레이어끼리는 서로 볼 수 없음 — 커닝 방지).
5. 제한시간 종료(또는 **End now**) → 자동 제출 → AI 채점 진행률 표시 → **결과 화면**: 등수, 항목별 O/X·구현률, 각 플레이어의 AI 생성 UI(iframe), 기본/디테일 소계·총점.
6. **Restart** → 로비로 돌아가 다음 라운드.

### 플레이어 (`/client/`)

1. 방 코드 + 이름 선택으로 입장.
2. 게임이 시작되면 **목표 UI(렌더링 화면)** 를 보고, 그것을 재현하는 프롬프트를 작성합니다. 소스코드는 보이지 않습니다.
3. 제한시간이 끝나면 입력이 잠기고 **자동 제출**됩니다 (수정 불가).
4. 채점 후 결과를 확인합니다.

## 채점 방식

- 각 문제는 **기본 구현 / 디테일 구현** 두 종류의 체크리스트 기준을 가집니다.
- AI는 생성된 코드를 채점 기준과 비교해 **항목별 판정(O/X·구현률)** 만 반환합니다. **원본 프롬프트는 채점 단계에 넘기지 않습니다** ("10점 주세요" 류 개입 차단).
- **점수 계산은 서버가 결정적으로** 수행합니다: `총점 = 기본점수 × (1 − 디테일가중치) + 디테일점수 × 디테일가중치` (기본값 디테일 0.3 = 기본 70 / 디테일 30, 문제별 조정 가능). 동점 시 디테일 점수 우선.

## 문제 / 바리에이션 작성 가이드

관리자 콘솔에서 문제를 만들 때:

- **목표 UI**(html/css/js)는 자체 완결형 한 화면이어야 합니다 (외부 라이브러리/폰트/이미지/네트워크 금지). 인터랙션이 필요하면 순수 바닐라 JS로.
- **채점 기준**은 반드시 **생성된 코드로 검증 가능한 구체적 항목**으로 작성하세요. 예: "`<button>` 요소가 있다", "`border-radius`로 둥근 모서리", "'Submit' 텍스트를 포함한다", "클릭 시 패널이 토글된다". "예뻐 보인다" 같은 모호/미적 표현은 피하세요.
- **바리에이션**: 한 문제에 여러 시각적 변형(다크 테마, 컴팩트 등)을 등록할 수 있습니다. 바리에이션은 **base 문제와 동일한 채점 기준**으로 채점됩니다 — 따라서 채점 기준과 충돌하지 않는(기준-중립적인) 변형으로 만드세요. 문제 편집 화면에서 관리합니다.

시드 문제들은 `seed/data/*.ts`에 있으니 작성 예시로 참고하세요.

## 재접속

- **플레이어**: 게임 도중 새로고침·네트워크 끊김이 발생해도, 같은 방 코드+이름으로 자동 재입장해 프롬프트 텍스트·남은 시간·화면을 복원합니다.
- **호스트**: 연결이 끊겨도 방은 약 45초의 유예 시간 동안 유지되며, 재접속하면 같은 방을 다시 확보합니다. 유예 시간 내에 돌아오지 않으면 방이 정리되고 플레이어에게 종료가 통지됩니다.
- 알려진 제한: 페이지를 완전히 새로고침한 뒤 바리에이션 라운드에 재접속하면 목표 화면이 base 렌더로 표시될 수 있습니다 (채점에는 영향 없음).

## 아키텍처

```
Node 서버 (단일 프로세스)
  HTTP        정적 프론트 서빙 + 렌더 엔드포인트 + 관리자 REST(/api/*)
  WS(ws)      방/실시간 동기화 (로비·타이핑 미러·게임 상태 브로드캐스트)
  GameManager 인메모리 방 상태 + 서버 타이머 (권위 상태)
  SQLite      문제·바리에이션·채점기준·계정 (node:sqlite)
  LLMProvider 인터페이스 → ClaudeProvider / FakeProvider
  grading     implement → grade → 결정적 점수/등수 산출
```

- **인젝션 방어**: 플레이어 프롬프트는 `<`/`>`/`&`를 이스케이프해 격리, 채점 단계는 코드+기준만 봄, 생성/목표 UI는 엄격한 CSP + `sandbox="allow-scripts"`(same-origin 미허용) iframe에서만 렌더.
- **관리자 API**: 모든 `/api/*` 라우트는 `x-admin-password` 헤더 게이트를 통과해야 하며, 인증은 어떤 DB 변경보다 먼저 검사됩니다. 비밀번호 비교는 상수 시간.

## 프로젝트 구조

```
src/
  server.ts          HTTP + WS 부팅, 라우팅, 채점 연결
  http/              정적 서빙, 샌드박스 렌더(renderDoc/GenStore), LAN 배너
  game/              types, GameManager(방·phase·타이머·재접속), hub(WS 라우팅), select(문제 선택)
  db/                schema.sql + node:sqlite 접근 계층
  llm/               LLMProvider 인터페이스, ClaudeProvider, FakeProvider, 프롬프트 새니타이즈
  grading/           채점 파이프라인 + 결정적 점수 계산
  admin/             계정·문제·바리에이션 CRUD REST
  util/              상수시간 비교 등
public/
  client/            플레이어 앱     host/  호스트 앱(대시보드·룰렛·결과)
  admin/             관리자 콘솔     shared/ ws·dom 유틸
seed/                50문제 시드 데이터 + 타입
scripts/seed.ts      시드 러너
test/                node:test 단위·통합 테스트
docs/superpowers/    설계 스펙 + 구현 계획
```
