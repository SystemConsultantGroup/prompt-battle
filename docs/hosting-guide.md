# 호스트 가이드 (게임 진행)

호스트는 방을 열고, 문제를 고르고, 게임을 시작·종료하며, 결과를 큰 화면에 보여주는 진행자입니다. `/host/` 로 접속합니다.

> 서버를 아직 안 띄웠다면 [시작하기](getting-started.md)를 먼저 보세요.

---

## 1. 방 개설

1. `/host/` 접속 → **관리자 비밀번호**(`.env`의 `ADMIN_PASSWORD`) 입력.
2. 인증되면 **방 코드**가 생성됩니다 (예: `K7QX`). 이 코드를 플레이어들에게 알려주세요.
3. 플레이어가 입장하면 로비 목록에 실시간으로 나타납니다.

한 방의 최대 인원은 8명입니다.

## 2. 문제 선택 — 4가지 방식

로비에서 다음 중 하나로 문제를 정합니다. 선택 시 문제 난이도에 따른 **제한시간이 자동 설정**됩니다.

| 방식 | 동작 |
|---|---|
| **Direct pick** | 목록에서 문제를 직접 선택 |
| **Roulette** | 전체 문제를 대상으로 슬롯머신 회전 (서버가 당첨 결정) |
| **Category roulette** | 카테고리로 필터한 뒤 룰렛 |
| **Pick + random variation** | 문제를 고르면 서버가 그 문제의 **base 또는 등록된 바리에이션 중 하나를 랜덤 선택** (무엇이 나올지는 숨김) |

> **바리에이션 모드**는 같은 문제라도 시각적으로 다른 변형(다크 테마 등)이 나올 수 있어, 미리 답을 외워오는 것을 방지합니다. 어떤 변형이 뽑혔는지는 서버만 알고, 채점은 base와 **동일한 기준**으로 이뤄집니다. 바리에이션 등록은 [관리자 가이드](admin-guide.md#바리에이션) 참고.

### 제한시간 직접 지정

문제를 고르면 그 문제의 기본 제한시간이 자동으로 잡히지만, 로비의 **제한시간** 버튼으로 `30 / 60 / 90 / 120 / 150초` 중 하나를 직접 고를 수 있습니다.

- 문제를 **다시 고르면** 새 문제의 기본값으로 되돌아갑니다. 제한시간은 문제를 고른 **뒤에** 지정하세요.
- **로비에서만** 바꿀 수 있습니다. 진행 중 변경은 서버가 거부합니다 — 이미 내려간 마감 시각과 각 클라이언트의 카운트다운이 어긋나기 때문입니다.
- **다시 시작**하면 지정값은 초기화됩니다.

## 3. 게임 진행

1. 문제 선택 후 **Start** → 게임 시작.
2. **대시보드**에 **목표 화면**과 각 플레이어의 프롬프트가 **실시간**으로 표시됩니다.
   - 왼쪽에 플레이어들이 재현해야 하는 목표 UI가 그대로 뜹니다 (바리에이션이 뽑혔다면 그 변형). 프로젝터로 진행할 때 관객이 무슨 문제인지 볼 수 있습니다.
   - 오른쪽 카드에 각자의 프롬프트가 타이핑되는 대로 미러링됩니다.
   - 플레이어끼리는 서로의 프롬프트를 볼 수 없습니다 (커닝 방지). 오직 호스트만 전체를 봅니다.
3. 제한시간이 끝나거나 **End now** 를 누르면:
   - 모든 플레이어 입력이 잠기고 **자동 제출**됩니다.
   - AI가 각 제출을 구현·채점합니다. 진행률(`done/total`)이 표시됩니다.
4. **결과 화면**:
   - 등수
   - 각 플레이어가 **실제로 제출한 프롬프트**
   - 항목별 판정 (O/X · 구현률)
   - 각 플레이어의 **AI 생성 UI**(iframe로 렌더)
   - 기본/디테일 소계와 총점
5. **Restart** → 로비로 돌아가 다음 라운드를 준비합니다 (플레이어는 그대로 유지, 프롬프트 초기화).

## 4. 재접속 / 연결 유예

- **호스트가 끊겨도** 방은 약 **45초**의 유예 동안 유지됩니다. 그 안에 `/host/`로 다시 접속하면 같은 방을 재확보합니다. 유예를 넘기면 방이 정리되고 플레이어에게 종료가 통지됩니다.
- **플레이어가 게임 중 끊기면** 슬롯이 유지되어 같은 이름으로 재입장 시 프롬프트·남은 시간·목표 화면(바리에이션 포함)이 복원됩니다. 약 **2분** 내에 돌아오지 않으면 슬롯이 자동 정리됩니다.

## 5. 진행 팁

- 호스트 화면은 프로젝터/공유 화면에 띄우고, 플레이어는 각자 기기로 접속하는 구성이 좋습니다.
- 룰렛/바리에이션 모드는 **당첨을 서버가 결정**하므로 결과를 신뢰할 수 있습니다 (클라이언트 조작 불가).
- 채점 품질은 문제의 **채점 기준 작성 품질**에 달려 있습니다 — [관리자 가이드](admin-guide.md#채점-기준-작성-가이드) 참고.
