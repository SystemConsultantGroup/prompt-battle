# 관리자 가이드 (계정 · 문제 · 바리에이션 · 테마 · 채점)

관리자 콘솔(`/admin/`)에서 플레이어 계정과 문제(및 바리에이션)를 관리합니다. `.env`의 `ADMIN_PASSWORD`로 로그인합니다.

> 모든 `/api/*` 요청은 `x-admin-password` 헤더 게이트를 통과해야 하며, 인증은 어떤 DB 변경보다 먼저 검사됩니다(비밀번호 비교는 상수 시간).

---

## 사이트 테마

콘솔 하단의 **사이트 테마**에서 카툰 또는 할로윈을 선택하고 **테마 저장**을 누릅니다.

- 기본값은 **카툰**입니다. 기존 `public/styles.css`는 원본 그대로 유지하며, 카툰 선택 시 추가 스타일을 적용하지 않습니다.
- 플레이어·호스트·관리자에 공통으로 적용됩니다. 다만 **페이지를 새로 열거나 새로고침할 때만** 현재 설정을 읽습니다.
- 이미 열린 화면은 관리자 저장이나 WebSocket 재연결로 바뀌지 않습니다. 저장한 관리자 화면도 새로고침 전까지 기존 테마를 유지합니다.
- 방 생성 시 고정하는 설정이 아닙니다. 설정 변경 후 기존 방에 접속한 플레이어는 호스트와 다른 테마를 볼 수 있습니다.
- 문제의 목표 UI와 AI 생성 결과 iframe, 프롬프트 및 채점 기준은 변경하지 않습니다.
- 설정은 SQLite `app_settings` 테이블에 저장합니다. 재기동해도 **같은 DB 파일**을 사용하면 유지됩니다. 파드 교체까지 보존하려면 [영속 저장 안내](hosting-guide.md#sqlite-영속-저장과-단일-파드-운영)를 따르세요.
- 최초 기동 시 테이블은 자동 생성됩니다. 기존 DB의 데이터나 이미 저장한 테마를 초기화하지 않습니다.

관리자 API:

- `GET /api/settings/theme` — 현재 선택과 지원 테마 목록. 관리자 인증 필요.
- `PUT /api/settings/theme` — `{"theme":"cartoon"}` 또는 `{"theme":"halloween"}`. 관리자 인증 필요. 미등록 ID는 400.
- `GET /theme.css` — 인증 없는 화면 로딩용 CSS. 현재 테마 CSS만 연결하며 `Cache-Control: no-store`로 새 페이지마다 다시 조회합니다. 기존 `/api/*` 인증 정책은 그대로 유지합니다.

### 새 테마 추가 시 원본 보존 계약

1. **`public/styles.css`와 카툰 테마의 기존 화면을 수정하지 않습니다.** 색상·간격·폰트·배경·상호작용·반응형·모션을 포함합니다.
2. 새 테마는 `public/themes/<id>.css`에 추가 스타일로 작성하고 `src/config/themes.ts`에 등록합니다.
3. `public/themes/cartoon.css`는 설명 주석만 있는 빈 스타일시트여야 합니다. 카툰용 덮어쓰기나 리팩터링은 금지합니다.
4. 새 관리자 설정 UI의 CSS는 `.theme-settings` 내부에만 제한합니다. 기존 계정·문제 패널 순서와 스타일을 보존합니다.
5. `test/http/cartoon-preservation.test.ts`의 원본 해시를 바꿔 테스트를 통과시키지 않습니다.

## 계정

플레이어가 사용할 이름을 등록합니다. **비밀번호는 없습니다** — 방 코드로 입장을 게이트합니다.

- 이름 추가 / 삭제.
- 같은 이름은 한 방에서 동시에 한 명만 사용할 수 있습니다.

## 문제

문제 하나는 **목표 UI(html/css/js) + 채점 기준 묶음**입니다.

- **생성 / 수정 / 삭제** 지원. (수정은 `PUT /api/problems/:id`)
- 필드: 제목, 카테고리, 난이도, 제한시간(초), 디테일 가중치, 목표 html/css/js, 채점 기준 목록.
- 시드된 50개 문제가 이미 있으면 그대로 쓰거나 참고용으로 복제·수정할 수 있습니다.

### 목표 UI 작성 규칙

- **자체 완결형 한 화면**이어야 합니다. 외부 라이브러리·폰트·이미지·네트워크 요청 금지.
- 인터랙션이 필요하면 **순수 바닐라 JS**로 작성하세요.
- 목표 UI와 생성 UI는 모두 엄격한 CSP + `sandbox="allow-scripts"` iframe에서만 렌더됩니다.

### 채점 기준 작성 가이드

채점 기준은 **생성된 코드로 검증 가능한 구체적 항목**이어야 합니다.

| 좋은 예 | 피해야 할 예 |
|---|---|
| `<button>` 요소가 있다 | 버튼이 있다(모호) |
| `border-radius`로 둥근 모서리 | 예뻐 보인다 |
| 'Submit' 텍스트를 포함한다 | 적절한 라벨 |
| 클릭 시 패널이 토글된다 | 인터랙션이 자연스럽다 |

- 각 기준은 **기본(basic)** 또는 **디테일(detail)** 종류를 가집니다.
- 미적·주관적 표현("세련된", "조화로운")은 피하세요 — AI가 일관되게 판정하기 어렵습니다.
- 작성 예시는 `seed/data/*.ts`를 참고하세요.

## 바리에이션

한 문제에 여러 **시각적 변형**(다크 테마, 컴팩트 레이아웃 등)을 등록할 수 있습니다. 호스트의 "Pick + random variation" 모드에서 base 또는 변형 중 하나가 랜덤으로 뽑힙니다.

- **문제 편집 화면**에서 관리합니다 (문제를 먼저 저장해야 추가 가능).
- **"Prefill from base"** 버튼: base 문제의 html/css/js를 폼에 복사해와 편집합니다 — 처음부터 작성할 필요가 없습니다.
- 바리에이션은 **base 문제와 동일한 채점 기준**으로 채점됩니다. 따라서 채점 기준과 충돌하지 않는(**기준-중립적인**) 변형으로 만드세요.
  - 예(OK): 색 테마만 바꾸기, 간격/폰트 크기 조정.
  - 예(주의): 기준이 "'Submit' 텍스트 포함"인데 변형에서 라벨을 바꾸면 채점이 어긋납니다.

### API (참고)

바리에이션은 콘솔 UI로 관리하지만, 프로그래밍 접근도 가능합니다:

- `POST /api/problems/:id/variations` — 바리에이션 추가. body에 `fromBase: true`를 주면 base 코드로 자동 시드(명시한 필드가 우선).
- `DELETE /api/variations/:id` — 삭제.

## 채점 방식

- 각 문제는 **기본 구현 / 디테일 구현** 두 종류의 체크리스트 기준을 가집니다.
- AI는 생성된 코드를 채점 기준과 비교해 **항목별 판정(O/X · 구현률)** 만 반환합니다.
- **원본 프롬프트는 채점 단계에 넘기지 않습니다** — "10점 주세요" 같은 개입을 차단합니다.
- **점수 계산은 서버가 결정적으로** 수행합니다:

  ```
  총점 = 기본점수 × (1 − 디테일가중치) + 디테일점수 × 디테일가중치
  ```

  기본값 디테일 가중치 0.3 → 기본 70 / 디테일 30. 문제별로 조정 가능하며, 동점 시 디테일 점수가 우선합니다.

### 인젝션 방어

- 플레이어 프롬프트는 `<`/`>`/`&`를 이스케이프해 격리합니다.
- 채점 단계는 **코드 + 기준만** 보고 원본 프롬프트는 보지 않습니다.
- 생성/목표 UI는 엄격한 CSP와 `sandbox="allow-scripts"`(same-origin 미허용) iframe에서만 렌더됩니다.
